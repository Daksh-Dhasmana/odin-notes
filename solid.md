# SOLID Principles
- It is an acronym for 5 core design principles in object-oriented and component-based SDE.
- These principles help developers write code that is clean, maintainable, testable, and easy to scale as a project grows.

- Top 5 SOLID Principles
1) S- Single Responsibilty principle(SRP)
   - What it means: A class, module, or component should have only one reason to change, meaning it should only have one job or responsibility.
   - Why it matters: Keeps code modular so that bugs in one feature don't unintentionally break unrelated features.
2) Open/Closed Principles
   - What it means: Software entities (classes, modules, functions) should be open for extension, but closed for modification.
   - Why it matters: You should be able to add new functionality without rewriting or editing existing, tested code (usually achieved through inheritance, polymorphism, or plugin architectures/strategies).
